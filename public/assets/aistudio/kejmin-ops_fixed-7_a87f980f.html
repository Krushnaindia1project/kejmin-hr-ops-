Task lifecycle

Created›Stage 1 · assignee›Stage 2…n · reviewers›Final approval›Closed
EventWho can do itWhat the system does
Create taskRoles with "Create tasks"Saves title, branch, location, importance, due date and the process path. Notifies the first assignee.
Mark stage doneThe person (or any member of the group) on the current stageMoves the task to the next stage, writes a score event, adds a line to the audit log, notifies the next person.
Send backAuditor, Finalizer, Owner, DeveloperReturns the task one stage, requires a reason, notifies the previous person. Points for the reversed stage are removed.
Final approvalLast person on the path (usually Finalizer)Closes the task, locks it from edits, adds proofs to the archive.
Every action aboveSystemWrites a timestamped entry (who, what, when) to the log. Only a Developer can read it.
OverdueSystem (scheduler)Flags the task in red, starts the escalation ladder below.
Change path / reassignDeveloper, OwnerAllowed only on open tasks. The change is logged with old and new assignee.

Scoring rules

ImportanceBase points
Low1
Medium3
High5
  • Points go to the person who completes a stage, one score event per stage.
  • Finished on or before the due date: 1.5× base points. After the due date: 1×.
  • A send-back removes the points for that stage; they are earned again when it is redone.
  • Reports total points by employee, team (location), branch, month, financial year (1 Apr – 31 Mar) or any custom date range.
  • Score events are append-only. Corrections are new events with negative points, never edits.

Attendance module

  • Each employee records check-in, break start / end and check-out from the web app or plant mobile app.
  • Working days follow a per-location calendar: weekly offs and a holiday list managed by Developer or Owner.
  • Worked hours = check-out − check-in − breaks. Late arrival and short hours are flagged against the shift.
  • Staff see only their own record. Coordinators see their team, Finalizer / Auditor / Owner see all locations they are scoped to.
  • Monthly attendance rate by employee, team or location feeds Reports and the payroll input export (CSV).
  • Corrections after the fact need a reason and are logged with the approver.

Stage changes, score events and audit entries are written by server functions, never directly from the browser. This is what stops a user from approving their own task or editing their own score.

Security and operations

Access

  • Sign-in with Firebase Auth. Passwords are hashed by Firebase and never stored by the app.
  • Role and scope live in custom claims; Firestore rules and the API both check them on every request.
  • Two-step verification is required for Developer and Owner accounts.
  • Deactivating a user ends their sessions straight away; their history stays.

Data and recovery

  • Hosted in the Mumbai region (asia-south1) so data stays in India.
  • Daily Firestore export to a separate bucket, kept 30 days; monthly copy kept 1 year.
  • Plant app works offline and syncs when the connection returns.
  • Uploaded proofs: images and PDFs only, 10 MB limit, virus-scanned before they are attached.

Build roadmap to production

  1. Phase 1 (wk 1–2): Firebase project, Auth, role claims, Firestore schema, security rules, audit log.
  2. Phase 2 (wk 3–5): Task and configurable multi-stage path engine (individual or group per stage), send-back, user management screens.
  3. Phase 3 (wk 6–7): Scoring engine, KPI dashboards (month / FY / date range), team scores, report export.
  4. Phase 4 (wk 8–9): Attendance with holidays and breaks, notifications, escalation, file proofs, plant mobile PWA with offline mode.
  5. Phase 5 (wk 10–11): Move prototype data into Firestore, UAT with Bengaluru and both plants, load test, backup restore drill, go-live on Cloud Run.

Ready to go live when

  • Every role has been tested against its row in the data model table, including attempts to read or write what it should not.
  • A backup has been restored successfully into a test project.
  • Owner and Developer accounts have two-step verification on.
  • Each location has completed one full week of real tasks and attendance in UAT.
Prototype today: this screen set runs in the browser with sample data. Moving to production replaces browser storage with the collections above; the screens and flows stay the same.

User manual

How to use KEJMIN OPS day to day. Open a topic to read it. You only see the screens your role allows, so some topics will not apply to you.
1. Getting started

Sign in

  1. On the first screen choose Sign in.
  2. Type your User ID and Password. Use Show to check what you typed.
  3. Press Sign in or the Enter key. The app remembers you on this browser until you log out.

Create an account

  1. Choose Create account.
  2. Fill in your full name, a User ID, a password and the same password again, then pick your branch and location.
  3. Press Create account. You are signed in straight away.
  • User ID: 3 to 20 letters, numbers, dots or underscores. It cannot be changed later.
  • Password: at least 6 characters.
  • Your full name must be unique in the company.
  • New accounts get the role Process Coordinator at Bengaluru Office and Plant Staff at the plants. An admin can change this under User management.

Sign out: press Log out at the bottom of the left menu. Always do this on a shared computer.

Moving around: use the left menu. The top bar shows your name, role and location. On a computer, press the arrow at the top of the menu to retract it to a slim bar with just the logo and icons, which gives the page more room. Hover over the slim bar to see the full menu. Press the arrow again to keep the menu open.

2. Dashboard

Shows four counts: Total tasks, In progress, Completed and High priority open. Below them, Branch workload shows how your tasks are spread across MIS, Operations, Sales, Accounts & Finance, Plant Coordination and HR.

Developer, Owner, Finalizer and Auditor see every task. Everyone else sees only the tasks they are on the process path for.

3. Tasks: see, finish and send back
  1. Open Tasks. The tiles at the top count your tasks: All tasks, Waiting on you, In progress, Overdue and Completed. Click a tile to show only those tasks.
  2. Use Search, Branch, Location, Importance and Sort by to narrow the list. Switch between List and Board (Not started, In progress, Completed). The app remembers your choice.
  3. Each task card shows its branch, location, importance, due date and a stage tracker. A blue tick means that person has finished, the orange ring is whose turn it is, and grey circles are waiting.
  4. Cards with Your turn are waiting on you. Press Mark done when your stage is really finished. The task moves to the next person and you earn points.
  5. Click the task title to open a level-by-level view of who has done what.
  6. The due line turns red with Overdue by N days when the date has passed.

Send back: if you are Auditor, Finalizer, Owner or Developer, a Send back button appears on tasks that are past their first stage. It returns the task one stage to the previous person.

When the last person marks it done, the card shows Completed.

Only mark a stage done when the work is really finished. The next person is notified by the task moving to them, and your score is recorded at that moment.
4. Workflow builder: create a task
  1. Open Workflow builder.
  2. Enter the Title, then choose Branch, Location and Importance (Low, Medium or High).
  3. Optional: pick a template (Employee onboarding, Plant daily report, Invoice approval, Attendance and payroll input) to fill in the stages for you.
  4. Under Process path, choose a person for Level 1, Level 2 and so on. Each level hands over to the next when marked done. Press + Add stage for more levels.
  5. Press Create task. You land on the Tasks screen with the new task at the top.

A title and at least one stage are required. Levels left blank are skipped.

In this version a new task always gets a due date 5 days from today. A date picker is planned for the live system.
5. KPI and scores
  1. Open KPI & scores.
  2. Choose From and To dates, or press This month or Financial year (from 1 April).
  3. Read the ranking: employee, score and a progress bar.

Points for each completed stage: Low 1, Medium 3, High 5. Finish on or before the due date and you get 1.5 times the points. Managers (Developer, Owner, Finalizer, Auditor) see everyone. Other staff see only their own score.

6. Attendance

The Attendance screen has up to four tabs: Today, My month, Team and Settings.

Clock in and out (Today tab)

  1. Press Clock in when you start work. The time is saved.
  2. Press Clock out when you finish. Hours worked are shown.

You can clock in once a day. If you forget to clock out, the day shows No clock-out afterwards and an admin should be told to correct it.

My month: pick a month with the arrows. You see working days, present, late marks, absent, hours worked, overtime and attendance percentage, then a day-by-day table and a colour calendar (Present, Late / half day, Absent, Holiday). Click a day to see its details. Managers can pick another employee from the list.

Team (Developer, Owner, Finalizer, Auditor): each person's status, clock-in and clock-out times and hours across the company today.

Settings (Developer, Owner): tick the working days, set shift start, shift end and grace minutes, and add or remove holidays (date and name).

StatusMeaning
PresentClocked in within shift start plus grace minutes and worked at least 4 hours.
LateClocked in after shift start plus grace minutes. Counts as a full day with a late mark.
Half dayWorked less than 4 hours. Counts as half a day.
AbsentWorking day in the past with no clock-in.
WorkingClocked in today and not yet clocked out.
Not clocked inWorking day today and you have not clocked in yet.
No clock-outA past day with a clock-in but no clock-out.
Holiday / Weekly offNot a working day. Hours worked on these days count as overtime.
Break tracking is part of the production plan (see the Attendance module above). For now the clock records only your in and out times.
7. Reports
  1. Open Reports.
  2. Set From and To, then narrow by Branch and Location if you wish.
  3. Use View by (Overall, Employee wise, Team wise or Role wise) and Select to focus on one person, team or role.
  4. Read the summary cards (total points, completion rate, overdue tasks, top performer) and the charts for employee scores, task status, importance mix, six-month trend, branch completion, team score and attendance rate.
  5. The Activity log at the bottom lists the latest actions.

Export CSV opens a text box with the data and copies it. Paste it into Notepad or Excel and save it as a .csv file. Print opens your browser's print window, which can also save as PDF.

8. Roles and access

The table lists each role, its branch and location scope and the actions it may take: create tasks, design paths, approve or send back, view all KPI, export reports, manage roles and manage users.

Create a custom role (Developer and Owner only): enter a role name, pick the branch and location scope, tick the permissions and press Create role. The role can then be given to users in User management.

9. User management (Developer and Owner)
  • Add user: enter a User ID, full name, a temporary password (one is suggested), role, branch and location, then press Create user. Tell the person their temporary password; they can change it in My profile.
  • Find users: search by name or User ID, or filter by role.
  • Edit: change name, role, branch or location.
  • Reset password: a new password is suggested. Press Reset and share it with the user.
  • Delete: the user can no longer sign in. You are warned if tasks are waiting on them, and past scores stay in the history.

You cannot delete the account you are signed in with, and at least one Developer account must always remain.

10. My profile
  • Details: change your name, phone and designation, then press Save changes. User ID, branch and location are locked; ask an admin to change them.
  • Profile picture: press Upload photo in the banner at the top of My profile and choose a JPG or PNG up to 5 MB. It is cropped to a square and shown in the top bar, on your profile and in User management. Press Remove to go back to your initial.
  • Security: enter your current password, the new one twice, and press Update password. Use 6 or more characters; mixing upper and lower case, numbers and symbols makes it stronger.
  • Activity: your recent actions and your own task, points and attendance figures.

12. Log (Developer only)

The Log menu appears only for Developer accounts. It keeps a timestamped record of what people do in the app. Each line shows the time (date, hours, minutes, seconds), the user, the type and what happened.

TypeWhat is recorded
Sign-inSuccessful sign-ins and sign-outs.
SecurityFailed sign-in attempts, password changes and password resets. Passwords themselves are never recorded.
TaskTask created (with branch, location, importance, due date and path), each stage completed with the points earned, and tasks sent back.
UserUsers created, new accounts registered, and changes to name, role, branch, location, phone or designation.
DeleteUsers deleted and holidays removed.
AttendanceClock in and out, working days, shift times, grace minutes and holidays added.
RoleCustom roles created, with their permissions.
ExportReport CSV exports and printouts.
UploadReserved for file uploads. The app has no upload feature yet, so nothing appears here for now.

Find something: set From and To dates (the last 30 days are shown at first), then narrow by User, Type or Search text. The summary line under the command shows how many events, users, events today and deletions match. The newest 200 lines are listed; press load more for older ones.

export csv puts the filtered lines in a text box and copies them. Paste into Excel or Notepad and save as .csv.

Nobody can edit or clear log entries from the app. In this prototype the log is kept in the browser, holds the latest 4,000 events and uses that computer's clock. The live system will keep it on the server where it cannot be changed.
13. Questions and fixes
ProblemWhat to do
I cannot sign inCheck the User ID and password (passwords are case sensitive). If you forgot it, ask a Developer or Owner for a reset.
"That user ID is already taken" when signing upChoose another ID, for example your first name, a dot and your initial.
I do not see a menu itemYour role does not include it. Ask an admin if you need access.
There is no Mark done button on my taskThe task is waiting on someone earlier in the path, or it is already finished. Open the task to see whose turn it is.
My day shows Late but I was on timeThe shift start and grace minutes in Attendance settings decide this. Ask an admin to check them.
My day shows No clock-outYou did not clock out. Ask an admin for a correction.
Export CSV shows a box instead of a fileThis is expected. Copy the text, paste it into Notepad or Excel and save it as .csv.
My data is different on another computerThis version stores data in the browser it is used on. Use one computer, or wait for the live system where everyone shares the same data.
